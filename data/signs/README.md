# 서울 STEP 9 표지판 스냅샷

서울 열린데이터광장의 안전표지(OA-15540)와 도로표지(OA-15017) 원본을 공간검색용으로 정규화했다. 출처 URL, 파일명, 파일 버전, 원본 SHA-256, 제외 건수, 이용조건은 `manifest.json`에 보관한다. 서울특별시 제공, 공공누리 1유형(출처표시). 파일 버전은 시설 현황 기준일이 아니다.

- 안전표지: 220,827건 중 관리번호 중복 20건, SHP geometry와 속성 X/Y 차이 5m 초과 720건 제외 → 220,087건. SHP의 `.prj` EPSG:5186을 확인하고 원본 geometry를 EPSG:4326으로 변환했다.
- 도로표지: 12,020건 중 관리번호 중복 8건, 검토 영역 밖 좌표 4건 제외 → 12,008건. 원본 위·경도 사용.
- 서로 다른 관리번호가 같은 좌표를 갖는 경우 유지한다. 두 출처의 실제 시설 중복 여부는 확정하지 않으며 화면 개수는 공개자료 레코드 수다.
- 검토용 좌표 사각영역은 서울 행정경계가 아니다. 서울 공식 자료를 조회하며, 누락 자료나 현장 설치 여부를 추론하지 않는다.
- 안전표지인덱스·규격코드를 실제 규제 내용으로 해석하지 않는다. 지도에는 `MGRNU` 또는 `표지일련번호` 원문을 표시한다. `S:`/`R:`는 내부 충돌 방지용 키이며 지도 번호에 덧붙이지 않는다.

`seoul-signs.json.gz`는 gzip JSON 배열이다. 행 필드는 manifest의 `schema`와 같다. 서버에서만 읽고 SHA-256을 검증하며, 클라이언트에는 입력 범위의 결과만 보낸다. 20,000건을 넘는 조회는 잘라내지 않고 범위 축소를 요청한다. 조사 사각형은 기존 앱과 동일한 북쪽 기준 위·경도 환산 방식이다.

재생성에는 `pyshp`, `pyproj`와 원본 증거 디렉터리가 필요하다:

```sh
python scripts/build_seoul_sign_snapshot.py /path/to/research/evidence
```

입력: `seoul_verified_file_OA-15540.body/.json`, `seoul_sign_csv.body/.json`. `.body`는 다운로드 원문, `.json`은 SHA-256이 들어 있는 다운로드 메타데이터다. 도로표지 CSV는 CP949다. 재생성 후 manifest의 원본 버전과 제외 사유를 재검토하고 `npm run build`로 검증한다. gzip 타임스탬프를 고정해 동일 원본은 동일 파일로 생성된다.
