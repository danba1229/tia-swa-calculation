# 조사 기능 신뢰성 수정 (2026-10-15)

## 변경 내용

- 조사 시작 전에 주소를 확인하고 같은 확정 주소·좌표를 통계, 개발계획, 교통시설, 지도에 전달한다. 개별 조회 버튼도 같은 과정을 거친다. 주소·범위 변경 후에는 이전 요청이 결과를 덮어쓰지 못한다. KOSIS 서버 역시 시도명 없는 주소를 카카오에서 확인한 뒤 행정구역을 판정한다.
- TIA DB는 `TIA_DATABASE_URL`, `DATABASE_URL`, `POSTGRES_URL`, `TRAFFIC_DATABASE_URL`, `SEOUL_BUS_DATABASE_URL`, `SEOUL_BUS_POSTGRES_URL` 순서로 기존 연결을 사용한다. `tia_projects` 및 `tia_sync_periods`의 별도 테이블을 사용한다. 새 전용 DB는 선택 사항이다.
- TIA 사업정보지원시스템의 대량 페이지 중복 응답을 피하기 위해 `numOfRows=1`로 조회한다. 요청당 최대 48페이지, 최대 동시 6개로 나누고 `sourcePage`로 이어 조회한다. 각 구간에서 첫 페이지/전체 건수를 재검증한다. 클라이언트는 원자료 식별값의 중복과 최종 전체 건수를 확인한다. 좌표 변환은 별도 20건 단위로 계속된다. 전체 수집 전에는 조회 중 상태와 진행량을 보여 준다.
- TIA 후보는 응답 후 DB에 저장한다. 일부 후보 저장을 전체 기간 수집 완료로 취급하지 않는다. 기존 일일 수집은 공통 DB 연결을 사용할 수 있고 최대 실행시간을 180초로 명시한다. 최초 장기간 조회는 원본 API의 단건 조회 특성 때문에 시간이 걸릴 수 있다.
- 경기 교통량은 확인된 저장자료를 먼저 반환하고 Next.js `after`에서 원문을 갱신한다. 분산 잠금·실패 대기·전체 페이지 검증을 유지하고 페이지 수집은 최대 3개씩 처리한다. 갱신 중에는 화면이 15초마다 확인하며, 실패 뒤에는 실패 문구를 유지한다. 최초 수집에는 자료가 준비되는 동안 진행 안내를 표시한다. 관측연도를 현재 연도로 바꾸지 않는다.
- 사업지 점은 클릭을 받지 않고 버스정류장보다 아래에 표시한다. 카카오가 사업지·정류장 요소를 감싸는 투명 영역도 클릭을 가리지 않도록 처리한다. 버스 누락 수는 실제 노선표의 기점 첫·막차와 배차간격을 기준으로 중복 제거하여 계산한다. 종점 운행시간이 없다는 이유로 기점 시간이 누락됐다고 안내하지 않는다.
- 지하철은 서울 시간표 실패 또는 이전 자료 사용 시 TAGO 보조 경로를 확인한다. 새 TAGO 자료가 성공하면 사용하지 않은 서울 경로의 실패 문구를 남기지 않는다. 최종 저장자료도 이전 자료이면 완료로 위장하지 않는다. 토요일 등 누락 운행일·방향을 표에 남기고 자료 미제공/이전 자료/조회 실패를 구분한다. 다른 요일의 시간을 복사하지 않는다.

## 검증

- `npm run build`: ESLint, Node 테스트 305개, Next.js 운영 빌드 통과.
- 신규 회귀 검증: 시도명 생략과 주소 변경 취소, 지역 판정, TIA 단건 페이지 이어받기/중복 검출/DB 캐시 변경 중 좌표 커서, 경기 비동기 갱신과 동시 요청 상한, 기점 시간의 중복 없는 누락 집계, 지하철 보조 조회/이전 자료/누락 토요일.
- `node scripts/check_investigation_reliability.mjs http://127.0.0.1:3021`: 로컬 운영 빌드의 화면을 실제 운영 API 응답 및 카카오 지도와 연결해 확인한다. 브라우저에 공개된 지도 키는 메모리에서만 재사용한다. 이 검사는 변경한 클라이언트를 검증하며, 운영의 기존 서버를 새 서버 코드로 바꿔 실행하는 검사는 아니다.
- 브라우저 통과 항목: 시도명 생략 주소의 확정 주소 전달, 축소 지도에서 보이는 정류장 클릭, 확대 후 서초구청(22863)·거리 54m 팝업, 기점 첫·막차 미제공 0개 노선, 신분당선 누락 토요일 행, 토지이용 엑셀 다운로드, 390px 화면 가로 넘침 없음, 자바스크립트 오류 없음. 기존 운영 TIA API의 응답 지연은 여전히 관측되므로 이 화면 검사에서는 요청 주소만 검증하며 새 서버의 운영 수집 성공으로 해석하지 않는다.

## 병합 후 확인할 운영 항목

PR 승인 전에는 main 또는 운영 설정을 변경하지 않는다. 승인 후 배포 시 다음을 실제 연결로 재확인한다.

1. 서초구 남부순환로 2584, 500×500m로 STEP 3·4·5·6이 조회되는지.
2. TIA `dbConfigured`, 원자료 수집 진행 및 마지막 완료·실패 구분. DB 권한이나 외부 API 접근은 코드 테스트만으로 보증할 수 없다.
3. 경기 저장자료의 빠른 첫 응답, 갱신 완료/실패 상태, 실제 관측월. 2024년 자료만 제공되면 그 연도를 유지한다.
4. 양재역 신분당선 및 경기 대표 역의 요일별 시간표. 공식 API가 특정 요일을 제공하지 않으면 수동확인필요를 유지한다.
5. 축소된 지도에서 서초구청 정류장 클릭과 기점 시간 누락 수.

외부 자료가 없거나 원본 서비스가 실패하는 상황 자체를 없앴다고 주장하지 않는다. 앱은 가능한 공식 경로를 조회하고, 확인된 자료·이전 자료·미제공 상태를 구분한다.
