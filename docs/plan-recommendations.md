# 주소 기반 교통계획 추천과 공개 Word 다운로드

## 범위

- 상단 조사 시작과 STEP 7의 계획 다시 찾기가 동일한 서버 추천을 실행한다.
- 기존 교통계획/공사 중인 시설계획 수동 입력은 보존하며 덮어쓰지 않는다.
- 2026-10-17 조사대장 73개 항목을 74개 문서 그룹으로 등록했다. P46은 도시정비형/주거를 분리한다. 검수된 Word 27개를 연결한다.
- 등록부는 조사 시점의 스냅샷이지 전국의 모든 최신 계획을 실시간 조사한 결과가 아니다.
- 승인본 대조 필요, 공식 요약자료만 확보, 변경 추진 중, 특정 구역 확인 필요를 보존한다. 원문의 사업기간은 현재 착공/준공 여부가 아니다.
- 추천은 지자체·범위 관련성이다. 노선 GIS/반경 교차/장래 교통수요 반영 판정은 하지 않는다.

## 자료와 판정

`data/plans/registry.json`은 메타데이터만 포함한다. Word/PDF/HWP 등 원자료는 Git이나 public에 넣지 않는다. `scripts/import_plan_registry.py <research_root>`는 조사 JSON, 원자료 목록, 최종 chapter2_style_delivery_audit, summary_output_manifest, plan_scopes.py(AST 리터럴만 읽음)를 대조하고 27개 파일 해시를 검증한다. 재생성 후 diff/근거/이용조건을 사람이 검토하여 PR로 승인한다. 파일명만 보고 최종본이나 적용 연도를 확정하지 않는다. 파일 내용이 바뀌면 새 hash/versionId이며 기존 저장 버전을 덮어쓰지 않는다.

법정동 10자리 코드와 상세 주소 결과를 서버에서 확인한다. 시도·시군구를 문자열 한 개로 잘라 추측하지 않는다. 강원도/강원특별자치도 이전·현재 코드를 명시적으로 보존한다. 광역권별 세부 경계를 검토하지 않은 A08/P11, 특정 구역 P46 등은 확인 필요로 남긴다. P31/A14의 수도권 연계는 직접 적용과 별도다.

계획 검토연도는 통계 수록연도와 별도다. 2026 이전 연도는 당시 유효본이 검증되지 않아 자동 선택하지 않는다. 기간 경과·계획기간 이전·시작연도 미확인을 표시하며, 기간 경과를 법적 실효로 단정하지 않는다. A14/P02/P22/P32 예외와 모란판교선 길이 차이를 유지한다.

선택은 브라우저에서 주소+검토연도+등록부 버전별로 저장한다. 서버에 사업지/선택을 추가 저장하지 않는다. 주소나 연도를 바꾸면 오래된 결과를 숨기고 요청을 취소한다. 수동 입력 표에는 자동 삽입하지 않는다.

## 접근 제어와 파일 연결

- 추천과 공식 출처 링크는 공개 가능하다. API 응답에 Drive ID, 해시 기반 저장 경로, 토큰, Word 내용은 포함하지 않는다.
- 2026-10-18 사용자 요청에 따라 Word 요약본은 로그인·별도 승인 없이 누구나 다운로드한다. 승인 목록 환경변수와 권한 확인 API/UI는 제거했다.
- 공개 범위는 등록부에 명시된 요약본뿐이다. 기존 계산기의 계정·프로젝트·원본 파일 접근 제어는 변경하지 않는다. 다운로드 코드는 계정 저장소나 세션을 읽지 않는다.
- 기존 PRIVATE Blob 저장소(`BLOB_READ_WRITE_TOKEN` 또는 해당 환경의 지원되는 Blob 인증)를 이용한다. 별도 저장소 생성이나 공개 전환은 하지 않는다.
- `node scripts/upload_plan_summaries.mjs <final-audit-path>`는 해시·크기 검사만 수행한다. `--apply`는 별도 업로드 승인 후 실행한다. 27개 합계 약 1.1MB이며 원문 PDF는 업로드하지 않는다. 업로드 후 실제 바이트를 다시 읽어 검증한다.
- 저장 키는 `tia-plan-summaries-v1/<SHA256>.docx`이며 덮어쓰지 않는다. 서버는 등록된 versionId만 받는다. 임의 Drive/Blob URL 및 경로는 받지 않는다.
- 응답은 private/no-store/nosniff/attachment이며 파일별 크기와 SHA-256을 검사한다. 이 캐시 정책은 로그인 제한을 뜻하지 않는다. 실패 시 다운로드를 중단하며 Blob URL 리디렉션이나 서명 URL 발급은 하지 않는다.
- 현재는 개별 Word 다운로드다. 원문/대용량 ZIP을 Vercel에서 만들지 않는다. 원문 버튼은 공식 페이지이며 전문·고시문·공식 요약을 구분한다. 재배포 이용조건은 별도 확인 대상이다.

## 검증 및 출시

1. `node --test tests/planRecommendations.test.mjs`: 지역·시군구·연도·예외·중복·비공개 메타데이터, 익명 다운로드, 임의 파일 경로 차단, 응답 바이트와 해시 실패를 테스트한다. 기존 계산기의 세션 검증은 유지한다.
2. `npm.cmd run build`: 전체 lint/test/Next 빌드.
3. Preview에서 실제 주소 추천, 조사 시작 연동, 주소 변경 중 이전 결과 차단, 선택 복원, 로그인 쿠키 없는 Word 다운로드를 확인한다.
4. 파일이 연결된 환경에서 Word를 다운로드하고 최종 감사파일의 해시와 비교한다. Vercel의 Preview 배포 보호는 앱 로그인과 별개이며, 이를 검증했다고 운영 공개 배포가 완료된 것은 아니다.
5. 저장소 연결은 환경별로 별도 확인한다. GitHub PR 승인은 운영 병합/배포 승인과 별개다. 승인 없이 main을 변경하지 않는다.

추가 비용 0원을 보장하지 않는다. 공개 다운로드는 반복 요청에 따른 저장소 읽기·전송·함수 사용량이 증가할 수 있다. 작은 등록 Word만 제공하고 원문은 공식 링크로 유지한다. 미연결 파일은 503으로 차단한다. 앱에 별도 다운로드 호출량 제한은 아직 없으며 운영 전 서비스 사용량 한도 점검이 필요하다.

## 2026-10-18 저장소 연결 검증

- 사용자 승인 후 기존 Preview 비공개 저장소에 27개 요약본(1,126,563 bytes)을 업로드하고, 모두 다시 읽어 등록부의 크기와 SHA-256이 일치함을 확인했다.
- 로컬 CLI의 OIDC는 development 환경이었다. Preview 연결에 development를 임시 추가한 뒤 업로드를 수행했으며, 작업 종료 후 preview 전용으로 복구한 상태를 재조회했다. 정적 토큰 발급이나 공개 전환은 하지 않았다.
- SDK의 `BlobNotFoundError`는 `name`이 일반 `Error`일 수 있으므로 업로드 도구에서 `instanceof`로 판별한다. 없던 파일의 최초 업로드가 실제 저장소에서 성공했음을 확인했다.
- 기존 계정 확인 과정에서는 계정을 복사/생성하거나 승인 목록을 설정하지 않았다. 이후 공개 다운로드로 변경하여 계정 연결은 더 이상 필요하지 않다.
- 운영 저장소는 별도이므로 Preview 업로드 성공이 운영 파일 연결을 의미하지 않는다. 운영 파일 업로드와 공개 사이트 검증은 병합·배포 단계에서 별도로 진행해야 한다.
