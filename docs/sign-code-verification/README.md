# 서울 표지인덱스와 경찰청 일람표 번호 비교

검토일: 2026-10-08 (한국시간). 최초 검증은 문서만 추가했다. 이후 사용자 요청에 따른 PR #3 표시 변경은 아래 「앱 표시 정책」에 별도로 기록한다. 운영 배포는 진행하지 않았다.

## 결론

**서울 `MRK_NUM` 전체가 경찰청 일람표 표지번호와 동일하지 않다. 원문 번호의 일괄 치환, 하이픈 뒷부분 제거, 500번대의 노면표시 자동 분류는 부적절하다.**

번호가 문자상 일치하는 항목과 실제 의미의 대응 검증은 구분해야 한다. 아래 83.0%는 번호 일치율이며, 현장 표지 내용의 정확도나 자동분류 확정률이 아니다. 서울 원본 정의서는 `MRK_NUM`을 ‘표지인덱스’로만 설명하고 경찰청 번호와의 공식 대응표를 제공하지 않는다.

## 기준 자료와 확인 수준

1. 서울시 안전표지 관련 정보 [OA-15540](https://data.seoul.go.kr/dataList/OA-15540/S/1/datasetView.do): `A064_P_안전표시_20260213.zip`, 원본 220,827건. 이번 앱에 채택한 관리번호·좌표 검토 통과 220,087건을 집계했다. 값은 219종(공란 1종 포함, 비공란 218종)이다. 원본 SHP/DBF의 `MRK_NUM`, `MGRNU`, `RMK`를 함께 읽었다.
2. 서울 T-GIS 테이블 정의서: `MGRNU`=표지관리번호, `MRK_NUM`=표지인덱스, `A064_KND_CDE`=표지규격. 규격코드에서 표지 내용을 추론하지 않는다.
3. 비교 문서: **「교통안전시설 일람표」 시행 2023.12.**. [경찰청 게시글](https://www.police.go.kr/user/bbs/BD_selectBbs.do?q_bbsCode=1001&q_bbscttSn=20240521062714460)과 [직접 PDF 링크](https://www.police.go.kr/component/file/ND_fileDownload.do?q_fileSn=157415&q_fileId=ced086c7-308f-43ae-ad09-8a25e1ab8f17)는 검색 색인에서 확인했지만, 직접 서버는 연결 시간초과/503으로 원문 취득에 실패했다. 한국도로교통공단 및 울산시 게시 사본도 이번 환경에서 503이었다. 2026년 최신 법령 전체와의 동일성까지 검증했다는 뜻이 아니다.
4. 실제 PDF는 공개 재게시된 [자료 A](https://m.blog.naver.com/terraqua_official/224107473547)와 [자료 B](https://www.jwsafety.co.kr/index.php?page=view&pg=1&idx=18&hCode=BOARD&bo_idx=2&sfl=&stx=)에서 각각 확보했다. 두 파일은 **8,650,174바이트, SHA-256 `5cd5d09dc3d238639993ebfda8abae4e5db1bf39a7a019ef05fe88987e3755fe`로 완전히 동일**하다. PDF 내부 시행일 2023.12., 생성일 2023-12-07, 1쪽을 확인했다. 동일한 재게시본 둘을 확보한 것이며, 경찰청 서버의 원본과 바이트 단위로 검증한 것은 아니다.
5. 이 PDF에서 주의·규제·지시·보조 표지번호 144개와 노면표시번호 66개를 추출했다. 문자 좌표·글자 크기로 도안 치수 숫자를 제외하고, 표지번호 행은 별도로 수동 대조했다. `chart-code-set.json`의 x/y는 PDF 포인트 좌표이며 이름 사전이나 운영용 대응표가 아니다.
6. 서울 T-GIS 공개 진입 페이지는 403이었다. 비공개 메뉴나 인증을 우회해 코드표를 가져오지 않았다.

## 실제 오류를 만드는 반례

### 1. `220-1`을 `220`으로 자르면 차중량제한으로 잘못 해석

일람표에서 `220`은 **차중량제한**, `224`는 **최고속도제한**이다. 서울의 `220` 레코드에는 비고 `40t` 등이 있어 일람표와 부합하는 사례가 있다.

그러나 서울 `220-1` 6,032건 중 비고가 정확히 `30`인 기록 5,070건, `제한속도30`인 기록 88건, `40`인 기록 12건이 있다. 예:

| 관리번호 | 서울 표지인덱스 | 원본 비고 |
|---|---|---|
| 04-0000042053 | 220 | 40t |
| 04-0000253073 | 220-1 | 제한속도30 |
| 04-0000253037 | 220-1 | 제한속도30 |
| 04-0000170840 | 220-1 | 40 |

따라서 `220-1 → 220`은 부적절하며, `220-1 → 224 / 무조건 30km/h` 역시 전체 레코드에 확정 적용할 수 없다. `220-1`~`220-8` 계열은 총 9,860건이다. 원본 비고는 대응 추론을 뒷받침하거나 반박하는 보조 증거로 사용하며 공식 코드 정의로 대체하지 않는다.

### 2. `751`을 하나의 표지 종류로 확정할 수 없음

서울 `751`은 21,548건이며 일람표의 표지번호 목록에 없다. 비고에는 `어린이보호구역 해제`, `여기부터 속도를 줄이시오`, `우회전시`, `30 해제` 등 서로 다른 문구가 나타난다. 이를 ‘어린이보호’나 ‘속도제한’ 하나로 일괄 분류하면 오분류 가능성이 있다. `750`, `704`, `232`, `-Z` 등도 별도 정의 확인이 필요하다.

### 3. 500번대를 곧바로 노면표시로 분류해서는 안 됨

일람표의 `513`은 노면표시 **좌우회전금지**다. 반면 서울 표지 레이어의 `513` 비고에는 `점멸신호시 아래 버튼을 누르면 보행자신호가 들어옵니다`, `보행자작동신호기`, `직진후 좌회전` 등이 있다. 숫자가 일치해도 다른 체계의 코드일 수 있다는 반례다. 이번 C 그룹 892건은 ‘노면표시 확정’이 아니라 **번호 충돌 검토 대상**이다.

### 4. 같은 번호가 의미도 부합하는 사례는 존재

`219`=주차금지, `322`=횡단보도(지시표지), `428`=견인지역은 일람표 명칭과 서울 원본 비고에 같은 표현이 나타난다. 다만 해당 코드의 다수 비고가 공란이며 일부 비고는 다른 표현이므로, 이 사례를 전체 레코드의 현장 설치 내용 전수 검증으로 확대하지 않는다. 특히 `322`는 횡단보도 **표지판** 코드이며 STEP 10 횡단보도 시설 자체의 개수로 세지 않는다.

## 서초구 예시 재검토

주소: 서울 서초구 남부순환로 2584. 기존 주소 검색 좌표 37.483625 / 127.032683, 가로 500m × 세로 500m, 앱과 동일한 북쪽 기준 직사각형 계산.

- 안전표지 108건 중 **95건**은 일람표 표지번호와 문자열이 일치한다. 이는 확정 분류 건수가 아니라 대응 후보 건수다.
- 나머지 **13건**은 `220-1` 5건, `704` 1건, `751` 7건이다. 공식 대응 확인 전 `수동확인필요`로 유지해야 한다.
- 별도 도로표지 11건은 방향·목적지 안내 자료이며 이 경찰청 안전표지 번호표로 강제 변환하지 않는다.

## 구현 판단과 후속 검증 조건

- 현재 관리번호 표시를 일람표 번호로 **전면 자동 치환할 근거는 아직 부족하다**. 이번 작업은 검증 문서 추가이며 코드/지도/운영 데이터 변경은 없다.
- 대응을 적용하려면 서울 `MRK_NUM → 공식 표지 종류/번호` 코드사전과 적용 시점을 먼저 확인해야 한다. 확인된 코드만 명시적으로 연결하고, 나머지는 원래 인덱스·관리번호를 보존해 `수동확인필요`로 표시한다.
- 하이픈 접미사를 제거하는 일괄 정규식, 번호 첫 자리로만 분류, 빈 비고의 속도값 추정은 사용하지 않는다. 제한속도 수치와 표지 종류의 검증은 별개다.
- 최종 일람표 원본을 경찰청/공식기관에서 직접 확보해 재게시본 SHA-256과 대조하고, 선택한 기준판 이후 개정사항을 확인한다.
- 자료 제공기관에 코드사전을 요청하거나 현장 확인 자료를 수동 연결하는 작업은 실제 전송·수행하지 않았다.

## 재현과 보관

원본·검색 결과·접속 실패 응답·PDF 추출 텍스트·분석 스크립트는 조사 환경 `/workspace/sign-code-verification-2026-10-08/`에 보관했다. 최초 검증 커밋에는 작은 비교표·집계·비고 증거와 이 보고서만 포함했다. 이후 사용자의 앱 내 일람표 표시 요청에 따라 동일 재게시 PDF와 그 렌더링을 `public/reference/`에 추가했다. 파일 해시·변환 방법은 `chart-assets.json`에 기록했다. `verify.py`는 PDF 글자 위치 및 코드 집합의 수동 대조 단언문을 포함하며, 서울 레코드는 앱 스냅샷의 관리번호로 제한해 집계한다.

## 이전 앱 표시 정책 — 2026-10-08 (아래 10월 12일 정책으로 대체)

사용자가 **의미까지 확인된 자료만 파란 점, 나머지는 빨간 점**을 선택했다.

- 원본 관리번호·표지인덱스·좌표는 보존한다. API의 관리번호 필드도 변경하지 않는다.
- 일람표 표지번호 144종과 원문 문자열이 동일할 때만 지도에 **대응 후보 번호**를 표시한다. 색은 빨강이다. 노면표시 번호·접미사 정규화·미등록 번호·도로 안내표지는 `?`로 표시한다.
- 시설별 확인 근거가 등록되어야 파란 점이 된다. 현재 개별 의미 검증 완료 등록은 **0건**이다. 검토 상태는 관리번호·원본 코드·좌표와 묶어, 다른 시설이나 변경된 레코드에 확인 상태가 전파되지 않도록 한다. 테스트의 파란 점은 합성 fixture이며 운영 자료가 아니다.
- 서초구 예시 119건은 모두 빨강: 후보 번호 95건, `?` 24건(안전표지 13 + 도로표지 11). 비고의 일부 일치 사례를 전체 코드의 확정 분류로 확장하지 않는다.
- 왼쪽 카카오 지도 / 오른쪽 확대 가능한 일람표. 좁은 화면은 지도 아래에 일람표를 배치한다. 지도 오른쪽 아래 표의 제목은 `범례`. 선택해도 확인 상태의 색은 유지한다.
- 표시 일람표는 **2023.12 시행판**이다. 공개 재게시본 2곳이 동일함을 확인했으며 경찰청 서버 원본·이후 개정 검증은 미완료라는 사실을 앱에도 표시한다.

## 현재 앱 표시 정책 — 2026-10-12

사용자가 모든 자료를 추가 확인 대상으로 전제하고 단일 색상을 요청했다. 아래 정책이 이전 파랑/빨강 상태 구분을 대체한다.

- 서울시 좌표·관리번호·원본 인덱스를 유지한다. 개별 선택 상세의 **비고**에 `서울시 표지판 코드(표지인덱스): 220-1`처럼 원문을 표시한다. 도로 안내표지는 `서울시 표지종별`로 구분한다. 원본 코드 보존용 비고와 별도로 원본 DBF의 자유서술 `RMK`도 ‘원본 비고’에 표시한다. `751` 사용자 지정 규칙의 근거로 사용한다.
- 지도 점과 인출선은 모두 파랑(#2563eb)이다. 색은 표지판 위치만 나타내며 확인 완료를 의미하지 않는다. 제목 아래에 **모든 자료는 추가 확인이 필요합니다**를 상시 안내한다.
- 일람표와 번호가 문자상 동일한 항목은 대응 후보 번호로 표시한다. 아래 사용자 지정 코드와 계열은 명시된 매핑으로 표시하고, 아래 `751` 비고 규칙 및 표시 제외 규칙을 함께 적용하며, 그 밖의 미확인·도로 안내표지는 `?`를 유지한다. 접미사 제거 등 일반화한 변환은 하지 않는다.
- 지도 번호를 클릭하면 해당 레코드 위도·경도를 담은 카카오 공식 로드뷰 링크를 새 탭에서 연다. 점 클릭은 상세 선택이며 상세에도 로드뷰 링크가 있다. API 키 추가나 별도 외부 데이터 수집은 없다.
- 로드뷰 링크는 위치 조회를 지원한다. 촬영 영상 유무, 표지판 가시성, 방향, 촬영일 및 최신 현장 상태를 보증하지 않는다.
