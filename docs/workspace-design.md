# TIA Support 조사 워크스페이스

2026-10-08: 지도·자료 분할형(A)을 기본으로, 표를 넓게 검토하는 보기(B)를 추가했다.

- 왼쪽 조사 항목과 실제 조회 상태, 상단 주소·직사각형 범위, 본문 지도·자료를 분리한다.
- `분할 보기`, `지도 보기`, `표 넓게 보기`는 기존 지도 상태를 사용한다. 지도 DOM과 조사 단계 컴포넌트를 재생성하지 않아 입력값·선택·SDK 레이어를 보존한다. 지도 확대는 Esc로 종료한다.
- 1100px 미만은 지도와 자료를 세로로 배치한다. 768px 미만은 조사 메뉴가 가로로 스크롤된다. 표 내부 스크롤을 사용하며 문서 전체가 가로로 밀리지 않도록 한다.
- `app/workspace.css`는 `.research-workspace` 내부에만 적용한다. 지표 계산기 화면과 보고서 인쇄 스타일을 분리하고, 지도 마커의 크기·클릭 영역에는 공통 버튼 스타일을 적용하지 않는다.
- 첨두분석 표·달력의 글씨와 대비를 개선한다. 기존 좌표·반경·단위·기준일·누락 경고, API 조회와 계산, 백업 및 내보내기 로직은 유지한다.
- 사업지 중심은 주소 말풍선 없이 점으로 표시한다. 추천지점·대중교통 지도 레이어는 유지한다.
- STEP 2는 첨두일·첨두시간 분석을 먼저 표시하고, 가까운 지점은 작은 카드, 공식 출처와 추천 근거는 접기 영역으로 제공한다.
- 결과 열은 flex gap으로 간격을 관리한다. 숨겨진 STEP 개수와 무관하게 첫 표시 패널이 지도와 같은 상단에서 시작한다.

## 검증

주소 입력은 도로명·지번·건물명 2~100자로 후보를 검색한다. 150ms 입력 대기와 요청 취소를 사용하며 한글 조합 중에는 검색하지 않는다. 기다리는 동안 검색 중 문구와 로딩 표시를 즉시 보여준다. 움직임 줄이기 설정에서는 로딩 표시가 회전하지 않는다. 성공한 검색 결과(결과 없음 포함)는 입력 컴포넌트 메모리에 최대 50개, 5분간 보관해 같은 검색어를 다시 입력하거나 후보를 다시 열 때 즉시 재사용한다. 오류·취소된 응답은 캐시하지 않으며 검색 이력을 브라우저 저장소에 추가하지 않는다. 최대 6개 후보를 방향키/Enter 또는 클릭·터치로 선택하고 Esc로 닫을 수 있다. 선택 결과의 주소만 기존 사업지 입력에 전달하며 좌표는 기존 정밀 주소검색으로 다시 확인한다. 자동완성 오류나 결과 없음은 직접 입력을 막지 않는다.

`POST /api/address-suggestions`는 기존 서버 환경변수 `KAKAO_REST_API_KEY`를 사용한다. 도로명·지번의 개별 주소를 우선하고 결과가 없으면 건물명 검색을 수행한다. 행정구역·도로의 대표좌표를 개별 주소로 추천하지 않는다. 인증키·원본 오류·후보 좌표를 클라이언트에 전달하지 않는다.

`npm run build`는 ESLint, 기존 Node 테스트, Next 프로덕션 빌드를 순서대로 실행한다.

별도 터미널에서 `npm run dev -- --hostname 127.0.0.1 --port 3002`를 실행한 다음:

```sh
node scripts/check_workspace_ui.mjs http://127.0.0.1:3002
node scripts/check_address_autocomplete.mjs http://127.0.0.1:3002
```

이 검사는 별도 Chromium 프로필에서 실제 입력·추가·삭제, 8개 단계 이동, 지도/표 전환과 Esc, 레이어 토글, IndexedDB 재접속, JSON 백업·복원, XLSX 다운로드의 셀 값, 7개 화면 폭, `/embed`, 지표 로그인 화면을 확인한다. 스크린샷과 파일은 Git에서 제외된 `.preview-test-results/`에 저장된다.

주소 자동완성 검사는 150ms 대기, 검색 중 표시, 같은 검색어 재입력·후보 재열기의 요청 생략, 5분 후 재검색, 오류 재시도도 확인한다.

이 UI 검사는 라이브 공공 API의 최신 데이터 완전성이나 인증된 지표 계산 전체를 검증하는 테스트가 아니다. 개별 조회·계산·API 예외처리는 기존 Node 테스트가 담당한다. 변경은 별도 브랜치에서 PR을 만들고 사용자 승인 후 `main`에 병합한다. 운영 배포는 기존 GitHub `main` → Vercel 연결을 사용하고, 배포 후 GitHub 배포 상태와 공개 URL의 새 화면을 별도로 확인한다.
