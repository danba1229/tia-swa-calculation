# STEP 10 교통시설물 공개자료 지도

2026-10-25 확인. 서울·경기 사업지의 가로×세로 직사각형 안에 있는 **사업지 시·도 자료의 시설 대표점**을 표시한다. STEP 10에서만 별도 카카오 지도를 생성한다. 일반 과속방지턱과 도색형 가상 과속방지턱(이미지험프)은 서로 다른 종류이다.

모든 자료는 추가 확인 대상이다. 현재 공개자료를 연결한 부분 구현이며, 8종 시설의 두 지역 전수 자동조사가 완성된 것은 아니다. 미표시·자료 미연결·조회 실패를 시설 없음으로 판정하지 않는다.

## 연결 범위

| 항목 | 서울 | 경기 |
|---|---|---|
| 신호교차로 | 2025 교차로 대장 중 2026 T-GIS 횡단보도에 보행등이 있는 3,088점 | 미연결 |
| 비신호교차로 | 같은 대장 중 보행등이 하나도 없는 후보 35점 | 미연결 |
| 횡단보도 | 2021 SHP 유효 도형 37,109점 | 전국 표준데이터 중 일부 시군 14,489점 |
| 육교 | 2022 대장 149건 중 주소가 정밀 검색된 50건의 근사위치 | 미연결 |
| 회전교차로 | 미연결 | 양평군 52건 중 주소가 정밀 검색된 49건의 근사위치 |
| 버스정류장 | 기존 서울 공식 파일/DB 조회 | 기존 GBIS API 조회; 인증/수집 실패는 별도 표시 |
| 과속방지턱 | 2025 SHP, 종류 001, 유효 도형 6,791점 | 미연결 |

서울 교차로 440점은 신호구분 미확인으로 따로 표시한다(경보·점멸 225, T-GIS 미수록 130, 연등 표기 47, 자료 상충 38). 정적 스냅샷 총 72,988점에 조회 시 버스정류장을 더한다. 인출선 번호는 종류별 조사 순번이며 공식 시설번호가 아니다. 원본 식별자는 상세/CSV에 보존한다. 번호는 같은 범위 내 필터·지도 확대에 따라 바뀌지 않으며, 범위를 바꾸면 다시 부여한다.

## 공식 출처와 처리 근거

- [서울 횡단보도 SHP](https://data.seoul.go.kr/dataList/OA-15554/S/1/datasetView.do): 파일 버전 2021-08-09. A004 레이어만 사용. 포함된 부착형 신호등 A057은 교차로 신호 판단에 사용하지 않는다.
- [서울 험프 SHP](https://data.seoul.go.kr/dataList/OA-15541/S/1/datasetView.do): 파일 버전 2025-04-17. `A067_KND_C=001` 요철형, `002` 이미지형. 방지턱 높이·고원식 횡단보도 여부는 추정하지 않는다.
- [서울 교차로 SHP](https://data.seoul.go.kr/dataList/OA-15534/S/1/datasetView.do): 2025-08-14. 단일로 4,534건 제외, 교차로 종류 002~005만 사용.
- [서울시 교차로 및 횡단보도 시설·위치정보 (T-GIS)](https://data.seoul.go.kr/dataList/OA-23081/F/1/datasetView.do): 파일 2026-08-24, 횡단보도 21,776건(교차로관리번호 7,592개, 그중 4,040개는 단일로). `교차로관리번호`가 교차로 SHP의 `CSS_NUM`과 같은 체계다(같은 번호 7,443개, 교차로명 97% 일치, 중심 간 거리 중앙값 6.7m). 교차로 대장(단일로 제외 3,563점)의 분류에만 쓰며 점의 위치는 대장 그대로다.
  - 횡단보도 중 `보행등유무=유`가 하나라도 있으면 **신호교차로(보행등 기준)**.
  - 이름에 `(경보)`·`(경보N)`이 있으면 경보(점멸) 신호로 보고 **신호구분 미확인**.
  - 보행등이 모두 없고 2021 차량신호 제어기도 연결되지 않았으면 **비신호교차로 후보**. 차량신호만 있는 교차로일 수 있어 현장 확인이 필요하다.
  - 보행등이 모두 없지만 2021 차량신호 제어기가 연결됐으면 자료 상충으로 **미확인**.
  - 이름에 `(연등)`이 있으면(해당 횡단보도의 55%가 보행등 있음) 보행등이 없어도 비신호로 보지 않고 **미확인**.
  - T-GIS에 해당 번호가 없는 교차로 160점은 기존 2021 제어기 연결 기준을 그대로 쓴다.
- [서울 교통신호제어기 SHP](https://data.seoul.go.kr/dataList/OA-15538/S/1/datasetView.do): 2021-08-09. `CSS_NUM`으로 교차로에 연결한다. 연결 제어기가 모두 차량신호 형식 001~006이고 체계가 공란/005(경보)/011(철거)이 아니면 차량신호 근거로 비고에 남긴다. 현재 운영상태의 확정이 아니다.
- [전국횡단보도표준데이터](https://www.data.go.kr/data/15028201/standard.do): 공식 다운로드 UI의 50,000행 상한을 그대로 적용한 5페이지에서 경기 자료만 추출. 14,504행 중 중복 ID가 있는 15행을 모두 제외. 서울 횡단보도도 중복 ID 2행을 제외. `보행자신호등 유무`는 교차로 신호/비신호 판정에 사용하지 않는다. 행별 데이터기준일을 보존한다.
- [서울 육교정보](https://data.seoul.go.kr/dataList/OA-22361/F/1/datasetView.do): 기준일 2022-12-31. 149건 중 범위주소·모호한 주소 40건을 제외하고 109건 조회, 50건만 `PRECISE_ADDRESS` 성공. 나머지 59건 미표시. 이는 주소 일치이며 시설 중심·존치 검증이 아니다.
- [양평군 회전교차로 설치현황](https://www.data.go.kr/data/15140141/fileData.do): 파일명 버전 2025-12-09. 52건 중 49건 주소 정밀 검색, 3건 실패. 파일명 날짜를 실제 자료기준일로 사용하지 않는다. 기준일은 미확인이다.

경기 횡단보도에는 남양주·의정부·수원·양주·하남·여주·동두천·이천·파주·구리·성남 일부 구·광명·포천·과천 자료가 들어 있다. 해당 시군 안에서도 전수 수록을 보장하지 않는다. 실제 원문 시군구 목록은 manifest와 UI에 노출한다. 전국 다운로드 상한 때문에 누락된 지방자치단체가 있을 수 있다.

SHP 원본 CRS EPSG:5186을 확인하고 WGS84로 변환한다. 면의 내부 대표점을 사용하며 조사 범위와 면이 일부 겹쳐도 대표점이 밖이면 제외한다. 빈 도형/유효하지 않은 도형(험프 656건, 횡단보도 213건)은 임의 보정하지 않고 제외한다. CP949 확장 한글이 있는 EUC-KR 선언 파일은 CP949로 엄격하게 디코딩한다. 가까이 있다는 이유만으로 서로 다른 시설을 병합하지 않는다.

## 추가로 확인했지만 연결하지 못한 자료

- [전국과속방지턱표준데이터](https://www.data.go.kr/data/15028195/standard.do)는 행정안전부 자료로 이동한다. 연결된 `file.localdata.go.kr/file/speed_bump_info/info`가 이 환경에서 HTTP 403이어서 내용·도색형 구분을 검증하지 못했다. 인증이나 차단을 우회하지 않았다.
- [의왕시 육교현황](https://www.data.go.kr/data/15108960/fileData.do): 위도·경도 열이 약 197725 / 527586의 평면좌표값이다. CRS 미확인 상태에서 위경도로 사용하지 않는다.
- [여주시 교차로 현황](https://www.data.go.kr/data/15109723/fileData.do): 교차로번호·그룹·검지기 채널 정보이며 시설 좌표와 신호/비신호 구분이 없어 제외했다.
- [경기도 도로대장 육교](https://www.data.go.kr/data/15128895/fileData.do): 경기 포털 연결 및 실제 좌표 검증을 완료하지 못했다. 포털 접근 실패가 자료 부존재를 뜻하지 않는다.
- 서울 교차로 대장에 없는 소규모 교차로의 위치, 서울 회전교차로 전수 위치대장, 경기 비신호 운영구분 대장, 경기 신호교차로·도색형 구분 험프의 검증된 위치자료가 추가로 필요하다. 표지판 위치·지도 원형 도로·신호제어기 부재로 시설을 추정하지 않는다.

따라서 남은 작업은 위 자료의 공개 다운로드/API 확보, 좌표계 및 시설 단위 검증, 비신호 운영 분류 확인이다. 연락이 불가능한 조건에서 검증되지 않은 위치를 채워 넣지 않는다.

## 조회와 갱신

- `GET /api/traffic-facilities?lat=…&lng=…&width=…&height=…&region=seoul|gyeonggi`.
- 좌표/범위를 검증하고 1~10,000m, 최대 15,000점으로 제한한다. 실패 시 이전 범위 자료를 현재 결과로 표시하지 않는다.
- API는 정적 gz 스냅샷의 SHA-256을 검증하고 기존 버스 조회를 합친다. 버스 오류만으로 다른 시설물 조회가 실패하지 않는다.
- **범위 조회는 자동이지만 공개파일 갱신은 아직 예약 자동화되지 않았다.** 현재 스냅샷을 사용한다. 기존 버스 갱신 주기는 그대로 따른다. 임의의 월간 시설물 갱신을 추가하지 않았다.
- 향후 수집 변경은 원본 해시·분류·좌표 검토 후 PR로 반영한다. 파일 버전, 조회일, 실제 자료기준일을 구별한다.
- CSV는 화면에서 선택한 종류의 전체 결과(페이지 제한 없음)를 내보내며 출처·좌표·위치 근거·원문 비고·추가확인 상태를 포함한다.

## 재현

Python에 pyshp, pyproj, shapely가 필요하다. 원본은 저장소 밖에 둔다. `source-files.json`의 URL/POST 인자와 SHA-256이 다운로드 출처를 고정한다. 공식 파일 해시가 바뀌면 자동 승격하지 않고 수집을 중단한다.

```sh
python -m pip install -r scripts/requirements-facilities.txt
python scripts/collect_facility_sources.py /tmp/tia-facilities
python scripts/geocode_facility_addresses.py /tmp/tia-facilities --geocode-base https://tia-support.vercel.app
python scripts/build_facility_snapshot.py /tmp/tia-facilities --checked-at 2026-10-26
npm run build
node scripts/check_step10_ui.mjs http://127.0.0.1:3036 --production-origin
```

주소 변환 명령은 권한 있는 TIA 배포에서만 실행한다. 공개 주소를 기존 geocode API에 최대 동시 3개씩 조회한다. 성공 응답만 재사용하고 입력 주소/기준일 변경 또는 실패 응답은 재조회한다. UI 검사는 로컬 빌드를 카카오 허용 origin으로 브라우저 안에서 렌더링한다. 운영 파일을 수정하지 않는다. 실제 SDK/지도 타일 및 운영 주소검색을 사용하며 시설물 API는 로컬 빌드에서 실행한다. 카카오 공개 JS 키는 빌드 때 설정해야 한다. 서버 비밀키는 출력하거나 파일에 커밋하지 않는다.

## 검증 기록

- `npm run build`: ESLint, 기존 포함 Node 테스트 368개, Next 운영 빌드 통과.
- 브라우저: 서울 서초구 남부순환로 2584 / 1,000×1,000m에서 184점(횡단보도 72, 요철형 66, 버스 26, 이미지형 15, 신호교차로 후보 4, 신호미확인 1), 실제 카카오 지도 타일 31개, CSV 184행 확인.
- 종류 필터, 선택 상세, 로드뷰 좌표 링크, 범례와 인출선 겹침 방지, 다른 STEP에서 레이어/조회 제거, 잘못된 범위의 잔여 결과 제거, 390px 모바일 가로 넘침 없음, 서울→경기 전환 시 서울 시설 잔류 없음 확인. 로드뷰 링크 검증이며 실제 영상의 촬영일/시설 도안 판독 검증은 아니다.
- 경기 수원시청 주소 1,000×1,000m: 로컬 정적 횡단보도 34점. 로컬에 GBIS 서버 키가 없어 버스는 조회 실패로 표시되며 횡단보도 조회는 유지됨.
- 별도 기존 운영 GBIS API 읽기 검증: 수원 좌표 37.263/127.028, 1,600×1,600m에서 54개 정류장, 기반정보 버전 20261006, 중복 ID 없음. 해당 실제 응답의 STEP 10 버스 변환 함수도 54점 반환. 신규 STEP 10 운영 API의 배포 후 통합 검증은 승인·배포 뒤 필요함.
