# 지하철 운영사 시간표·GITS 최신 교통량 연결

## 변경 범위

- 신분당선은 운영사의 역별 평일 / **주말 및 공휴일** 표를 우선 사용한다. 선택 역을 재확인하고 단축 운행의 정자 행선지와 익일 시간을 보존한다. 신분당선 운영사 역 목록에서 코드를 읽으며 번호 순서를 추정하지 않는다.
- 수인분당선은 코레일 게시목록의 시행일이 지난 최신 공식 XLSX를 사용한다. 아직 시행 전인 파일은 제외한다. 평일/휴일, 상행/하행 시트의 **출발 행**을 읽는다. 토·일·공휴일은 휴일 시트 기준임을 화면에 명시한다. `수원시→수원시청`, `신수원→수원` 등 운영사 약칭은 명시적인 대응표로만 연결한다. 열차 종류는 파일에서 확정하지 못하므로 미제공으로 유지한다.
- 다른 노선은 기존 서울교통공사/TAGO 경로를 유지하고 시간표 캐시를 월간에서 20시간으로 줄인다. 운영사 자료가 없거나 연결이 실패하면 기존 API로 보완한다. 운영사 원문 링크·확인 시각·시행일을 표시한다. 신분당선 웹 표에는 시행일이 없으므로 확인 시각을 개정일로 표시하지 않는다.
- 경기 교통량 기본 출처를 **경기도 교통정보센터(GITS)**로 변경하고 경기데이터드림 기존 저장자료를 별도 출처 선택으로 유지한다. 둘의 측정값을 섞지 않는다.
- GITS 달력의 마지막 공개 날짜를 읽어 조회 가능 연도를 결정한다. 로컬 현재 연도를 관측 연도로 쓰지 않는다. 마지막 공개 날짜의 21개 일반국도 노선을 조회해 지점 목록을 만든다. 따라서 목록은 해당 기준일의 지점이며, 해당 연도의 모든 과거 지점을 완전히 열거한다는 뜻은 아니다.
- 월 선택은 공개 연도의 조회 가능 기간이다. 각 월에 실제 관측값이 있다는 보장은 하지 않으며 선택한 지점·주간을 조회하여 확인한다. 마지막 공개 날짜 이전의 최근 월~일을 기본 선택한다. **달력상 완결된 주간**이며, 168시간 관측 완전성은 조회 후 별도로 검증한다.
- 선택 주간을 공식 HTML 표의 모든 페이지에서 수집한다. 방향 0은 목록 작성에만 사용하며 분석값은 방향 1·2에서 수집한다. 24개 시간대 순서, 날짜/노선/방향, 중복, 페이지 반복·전체 건수, 일합계를 검증한다. 한쪽 방향이나 일부 날짜가 없으면 결측으로 남긴다.
- GITS 원자료 다운로드는 선택 지점·월의 두 방향 JSON이다. 기존 경기데이터드림 월 전체 다운로드는 유지한다.

## 자동 갱신과 운영 조건

| 대상 | 확인 방식 | 사용자 화면 반영 |
|---|---|---|
| 신분당선 16개 역, 수인분당선 공식 파일 | 매일 05:00 KST 예약 실행. 20시간 미만의 캐시는 재사용 | 다음 교통시설 조회. 공식 원문의 버전·확인 시각이 달라지면 요약 캐시도 바뀜 |
| 기타 지하철 API | 저장 후 20시간이 지난 첫 조회 | 다음 교통시설 조회 또는 만료 항목 재시도 |
| GITS 공개 연도·기준일 지점 목록 | 매일 05:00 KST 예약 실행, 조회 시에도 만료 검사 | 사전조사·첨두 분석 진입/저장자료 새로고침 |
| GITS 선택 지점·기간 관측값 | 20시간이 지난 뒤 해당 기간 조회 | 해당 주간 재조회. 모든 지점·연도를 매일 내려받지는 않음 |
| 기존 경기데이터드림 전체 자료 | 매일 05:30 KST 예약 실행 + 기존 조회 후 배경 갱신 | 기존 출처 선택 후 재조회 |

공개기관의 변경을 즉시 수신하는 푸시 방식은 아니다. 기관이 공개한 뒤 위 확인 주기에 따라 반영하며, 새 자료의 검증에 실패하면 이전 검증 자료를 유지하고 갱신 실패를 표시한다. 기존 공통 캐시의 이전 자료 허용 기간은 최대 45일이다. DB가 없으면 임시 메모리로 조회할 수 있지만 예약 작업은 저장 실패를 성공으로 보고하지 않는다. 신분당선 웹 표의 미래 시행일은 원문에서 제공되지 않아 자동 판별할 수 없다.

열어 둔 조사표·이미 다운로드한 CSV/엑셀을 자동으로 덮어쓰지 않는다. 새 조회에서 반영한다. 경기 교통량 원자료는 연 단위 공개이며 사이트가 매일 바뀌거나 실시간 통행량이 된다는 뜻은 아니다.

추가 외부 API 키는 필요 없다. 기존 `CRON_SECRET`, `SEOUL_BUS_DATABASE_URL` 또는 `SEOUL_BUS_POSTGRES_URL`과 경기 기존 저장소 환경변수를 사용한다. 예약 실행은 승인 후 운영 배포부터 활성화된다. 사이트의 정상적인 익명 세션/폼 토큰만 사용하며 토큰·쿠키는 저장하거나 로그에 남기지 않는다. HTTP 리다이렉트, 임의 파일 호스트, 무제한 파일·페이지 수집은 허용하지 않는다.

## 재현·검증

- `npm run build`: ESLint, Node 회귀 테스트 **317개 통과**, Next 운영 빌드 통과.
- `NODE_USE_ENV_PROXY=1 npm run start -- --port 3022`: 관리형 클라우드의 세션 프록시를 사용하는 로컬 확인. 이 환경변수는 운영 Vercel 설정에 추가하지 않는다.
- `node scripts/check_official_transport_ui.mjs http://127.0.0.1:3022`: 실제 로컬 GITS 엔드포인트와 기록된 공개 시간표 응답을 사용한다. 주소·지하철 API는 UI fixture이며 실제 주변역 검색 검증으로 주장하지 않는다. 주간 결과, CSV, 지점·월 JSON, 출처 전환 시 이전 결과 제거, 지하철 출처·시행일, 모바일 가로 넘침을 확인한다.
- `tests/officialTransport.test.mjs`: 미래 시행일 배제, 약칭/출발 행, 주말 구분, 원문 형식 변화, 페이지 반복, 방향·기간 불일치, 부분 자료의 완전자료 덮어쓰기 방지, 만료 재조회, 예약 작업 인증을 검증한다.
- 공개 원문 표의 작은 발췌본은 `tests/fixtures/official-transport/`에 저장한다. 코레일 샘플은 처음 14개 열차만 포함하므로 전체 운행표로 사용하지 않는다. `suin-result.json`은 실제 전체 파일에서 계산한 UI 검증용 응답이다.

운영 DB 저장·예약 실행 자체는 로컬에서 운영 자격증명을 사용하지 않았으므로 승인 후 배포 확인이 필요하다. 기존 PR #12의 개발계획 레코드 식별 수정은 이 작업과 별개이며 여기에 포함하지 않는다.
